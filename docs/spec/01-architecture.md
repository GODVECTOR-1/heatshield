# 01 · Architecture

One Next.js (App Router) + TypeScript repo, hosted on Vercel. `lib/types.ts` is the single contract.

## Who builds what
| Owner | Files |
|---|---|
| **Builder (you + Claude)** | `lib/types.ts`, `lib/client/*`, `docs/`, the hand-written expectation tests (E1 goldens, WBGT tolerance cases, status/ack cases) written *before* the engine |
| **Antigravity (backend)** | `lib/engine/*`, `lib/sim/*`, `lib/weather.ts`, `lib/store.ts`, `lib/status.ts`, `lib/auth.ts`, `lib/problem.ts`, `app/api/*`, `data/*` (except the weather fixtures and climatology below), `scripts/*` |
| **v0 (frontend)** | `components/*` and the UI of `app/*/page.tsx`. Output is copied in by hand; v0 never syncs to main and never touches `lib/` or `package.json` |

v0 and Antigravity treat `lib/types.ts` as read-only. Only the builder edits it.

## Data flow
```
 SUPERVISOR BROWSER                                        WORKER PHONE (PWA)
 lib/weather.ts ── Open-Meteo (unixtime, wind m/s)         QR #fragment {v, siteId, token, sessionId}
   → hourly WBGT sun/shade                                   → GET /api/session/:id  (cache in localStorage)
 lib/engine/planner → schedule (15-min slots)                → GET /api/site + /api/profile/:workerId
   → POST /api/session  ── session:{site}:{sessionId} ──►    lib/client/session.ts
   → show QR                                                   advanceTo(simNow) every tick / on resume
 board: GET /api/crew/:crewId/status (1 MGET)                  lib/engine/{physiology,risk}
        POST /api/ack                                          single-flight latest-only queue
                    ▲                                              │ POST /api/status (level only)
                    └──────── Supabase Postgres ◄─────────────────┘
                    tables session / status / ack, expires_at = now + 24 h
 sign-in: supervisor = Supabase Auth email link · worker = Supabase anonymous user + QR join token
 /evidence ← public/evidence.json ← npm run sim (lib/sim + lib/engine, frozen params)
```
The phone never fetches weather or runs the planner. Both come from the session record, so the phone and the board always agree.

## Stack
| Need | Choice |
|---|---|
| Framework / hosting | Next.js App Router + TS on Vercel, with a preview per push and a production promote each evening |
| Shared state + sign-in | **Supabase** (`@supabase/supabase-js`): Postgres for session/status/ack, Auth for sign-in. See [03](03-api-and-storage.md) |
| AI text | **Gemini** (server only, optional): plan summary on the board + build-time translation drafts. See [03](03-api-and-storage.md#gemini-optional-text-only) |
| QR | `qrcode` npm package (deterministic, no AI) |
| Offline | Serwist (`@serwist/next`) with explicit rules only. See [10-dev-setup.md](10-dev-setup.md) |
| Weather | Open-Meteo forecast + archive (free, no key, CC BY 4.0 attribution) |
| Charts | Recharts (evidence page) |
| Fonts | `next/font` Noto Sans per script |
| Voice | `speechSynthesis` with a tone fallback |
| Tests | Vitest (`vitest run`) |

## Design choices locked by the review
- **Supervisor-owned snapshot.** WBGT and the schedule are computed once by the supervisor and stored in the session record.
- **Session isolation.** `sessionId = crypto.randomUUID()` is part of every key, so concurrent demos never collide.
- **One writer per key.** Status is written by the worker and ack by the supervisor. There is no compare-and-set.
- **Pure cores.** The engine, `applyStatus`, the queue reducer and the fragment parser are pure functions with node tests.
- **Production safety.** The in-memory store is used only off Vercel. Missing store vars in production return a 503.
- **AI never decides safety.** Gemini only writes prose; levels, alerts and the schedule come from the deterministic engine and planner.
